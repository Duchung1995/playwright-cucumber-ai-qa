1.3 Framework architecture

  • Custom World (src/support/world.ts) holds the page, a lazy page-object registry, typed API clients, scenario state, and lists of created entities to clean up.
  • Hooks (src/support/hooks.ts):
    • The browser launches lazily, so API runs never start one, and each scenario gets its own context.
    • Tracing is always recorded. On failure the trace is kept and a full-page screenshot is attached.
    • An After hook deletes created brands and users, even when the scenario failed.
  • POM (src/pages/): readonly Locator fields, intent-level methods, a shared Header component.
  • Deterministic locators: getByRole → getByLabel → getByTestId (data-test). No CSS or XPath.
  • Zero sleeps: web-first assertions plus waitForResponse. ESLint bans waitForTimeout, setTimeout and ElementHandles.
  • Typed API clients (src/api/) and zod schemas (src/schemas/).
  • Test data: unique slugs and emails, and checkout seeds an isolated customer.
  • Cucumber profiles: default, api, ui, smoke, dryrun. Reports go to JSON, HTML and a rerun file.
  • CI workflow (.github/workflows/ci.yml): type-check, lint, tests, report artifact, job summary.
  • Docs: README.md, CLAUDE.md, docs/requirements.md (REQ IDs ↔ @REQ-* tags), docs/ai-harness.md (with a mermaid diagram).
